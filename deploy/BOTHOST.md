# Деплой на Bothost.ru (через GitHub)

## Тариф
Нужен **платный** тариф (минимум Basic, 99 ₽/мес) — на бесплатном данные стираются,
а у нас склад хранится в базе. Платный даёт постоянную папку `data`.

## Репозиторий
`vverbawork-a11y/kroog-bot` (публичный), ветка `main`.

## Команда запуска
```
python autodeploy.py
```
(в проекте есть Procfile: `worker: python autodeploy.py`)

## Переменные окружения (Environment Variables)
Задаются в панели Bothost — НЕ в коде:

Реальные значения НЕ храним в репозитории — они в config_local.py (локально)
и в панели Bothost. Здесь только список переменных:

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_ID` | твой Telegram ID (куда приходят заявки) |
| `MANAGER_USERNAME` | username менеджера без @ |
| `CHANNEL_URL` | ссылка-приглашение на Telegram-канал |
| `DB_PATH` | data/kroog.db |

## Постоянное хранилище
База лежит в `data/kroog.db`. Папка `data` на Bothost сохраняется между
перезапусками и обновлениями — остатки склада не сбрасываются.

## Важно
Одновременно должна работать только ОДНА копия бота. Когда бот поднят на Bothost —
останови копию на Маке (закрой окно run.command или `pkill -f main.py`),
иначе будет ошибка Telegram «Conflict».


## Автоматическое обновление из GitHub

В Dockerfile и Procfile настроен запуск `python autodeploy.py`. Это управляющий
процесс, который запускает `main.py` и раз в 120 секунд проверяет последний push
в `main` через GitHub Actions workflow `miniapp-tests.yml`. Устанавливается только
успешно прошедший тесты коммит, который всё ещё является вершиной `main`.

### Первое включение

Один раз нажмите **«Сохранить и пересобрать»** в Bothost. Если в разделе «Запуск»
есть собственная команда, замените `python main.py` на `python autodeploy.py`.
После этого пересборка для обычных изменений Python, Mini App, фотографий,
шаблонов и Python-зависимостей больше не нужна. Пока старый контейнер не
пересобран, GitHub не может установить в него этот механизм извне.

### Как происходит обновление

1. После успешного CI загружается архив строго определённого SHA из нашего
   публичного репозитория по HTTPS; токены GitHub и Telegram для загрузки не нужны.
2. Код распаковывается в отдельный каталог, проверяется синтаксис и импорт точки
   входа. При изменении `requirements.txt` зависимости устанавливаются в отдельное
   виртуальное окружение, пока предыдущая версия продолжает работать.
3. Перед переключением повторно проверяется вершина `main`. Старый процесс
   завершается, SQLite сохраняется через штатный backup API, запускается новый.
4. Telegram и сервер Mini App должны успешно запуститься, а процесс — пережить
   10 секунд проверки. При неудаче запускается предыдущий код. Неудачный SHA не
   повторяется; исправление следует отправить новым коммитом.

Пауза при переключении возможна: одновременно работает только один Telegram
polling-процесс. При недоступности GitHub работающий бот не останавливается.

### Данные и восстановление

`DB_PATH` преобразуется в абсолютный путь. Склад, заказы и каталог `uploads`
не входят в архив обновления и не заменяются. Служебные данные и две последние
версии лежат рядом с БД в `.kroog-autodeploy/`, поэтому используйте постоянный
том Bothost. Резервная копия перед последним обновлением находится в
`.kroog-autodeploy/before-update.sqlite3`.

При возврате старого кода база автоматически не откатывается: это могло бы
потерять новые заказы. Миграции БД должны оставаться совместимыми с предыдущим
кодом. Изменения самого управляющего процесса, базового Docker-образа,
системных пакетов и настроек хостинга требуют пересборки Bothost.

### Проверка

Откройте `/api/release` на домене Mini App. После включения ответ содержит
`autodeploy.enabled: true`, фазу, SHA установленного коммита и время проверки.
При успешном обновлении SHA совпадает с последним проверенным коммитом `main`.
Секреты и пути файлов в ответ не попадают. Публичного endpoint для запуска
команд или пересборки нет.

- `KROOG_AUTOUPDATE=0` — отключить самообновление и запускать только bundled-код.
- `KROOG_UPDATE_INTERVAL` — период проверок в секундах, минимум 120.
- `KROOG_START_TIMEOUT` — ожидание старта новой версии, по умолчанию 90 секунд.

Если GitHub временно ограничит запросы, следующая проверка будет позже. Если
репозиторий станет приватным, потребуется изменить способ авторизованного
получения кода; пока бот продолжит работать на установленной версии.
